# 図の宿題

使い方ガイド（`docs/manual.html`）の図について、気づいたことを貯めておく場所。

**画面を直すたびに撮り直さない。**ここに書き足しておいて、手直しが落ち着いた
ところで、まとめて撮り直す。

```
node tools/figs/all.js
```

これで36枚がぜんぶ、そのときの画面に入れ替わる。使い方は `tools/figs/README.md`。

**流す前に、直した内容を公開しておくこと。**手元のファイルから撮ると
YouTube が動画を貸してくれず、図にエラーが写り込む。

---

## チョロさんとクローディアの約束ごと

### 宿題に足すとき

**決まった言い方は要らない。**図の話が出たら、クローディアが自分でここに
書き足す。「あとで直すね」で終わらせず、必ずこのファイルに残すこと。

チョロさんから念を押したいときは、こんな言い方でよい。

> 「これ、図の宿題に入れといて」

### 撮り直すとき

**クローディアが勝手に流さない。**チョロさんが「いいよ」と言ってから。

理由は3つ。
 ・撮る前に「直した内容を公開しておく」段取りが要る
 ・36枚が一度に差し替わるので、変更が大きくなる
 ・20分ほどかかる

チョロさんからの合図は、こんな言い方でよい。

> 「図を撮り直して」／「一段落したから、図を更新して」

### いつ言えばいいか

**クローディアから声をかける。**次のときに「そろそろ撮り直しませんか」と
提案すること。チョロさんが覚えておく必要はない。

 ・宿題が3件くらい溜まったとき
 ・ヘッダーや説明パネルなど、**多くの図に写る場所**をいじったとき
 ・ジャンル数が節目を越えたとき（画面の数字が図と食い違うため）
 ・公開の直前

### 自動で定期的に流すのはやめておく

やろうと思えばできる（GitHub Actions で毎週など）。ただし、
 ・YouTube の広告が写ることがあり、**人の目で見ないと気づけない**
 ・思わぬ画面（読み込み中、通信の失敗）のまま撮れてしまうことがある
 ・36枚が黙って差し替わり、誰も見ていない変更が積み上がる
ため、**撮ったら必ず目で確かめる**という前提を崩さない。

### 2026-09-05（3回目）── パネル画像7枚中5枚が全画面スクショの縮小版に化けていた事故を修正

2回目の直し（.fig-panelで320px幅に縮小）を見たチョロさんから
「ルーツマップ（地図全体）が要らないのに写り込んでいて、パネルの
文字が小さすぎて読めない」との指摘。実際に1枚ずつ見直したところ、
pnl1_top・pnl3_roots_books・pnl4_influence・pnl5_correction・
pnl7_amazonの5枚が、**パネルだけを切り出したはずが、地図を含む
全画面スクリーンショットを320pxに無理やり縮めたもの**に化けていた。

**原因**：fig04_gosenfuを撮り直すたびに`jpgにする.py`を実行していたが、
このスクリプトは`_out/`内の全PNGを処理する仕様。切り出す前の生の
全画面スクショ（pnl1_top.pngなど）が`_out/`に残ったままだったため、
既に正しく切り出し済みのdocs/img側jpgを、幅だけ合わせた「全画面の
縮小版」で毎回上書きしてしまっていた。

**直し方**：
- `#side-panel`の実座標をgetBoundingClientRectで実測（物理px換算で
  2160〜2800）し、7枚すべてパネル部分だけを切り出し直した
- 「音楽性・特徴」の見出しが欠けていた別件も判明：スクロールすると
  パネル上部の固定ヘッダーに本文が透けて重なる不具合があったため、
  スクロールせず最初の画面のまま下のほうを切り出す方式に変更
- `crop_panel_figs.py`に、処理後に生PNGを削除する後始末を追加し、
  この事故が二度と起きないようにした
- 7枚すべてを1枚ずつ目視確認してから公開（今回は本当に確認した）

528か所）は 2026-08-31 に v27.38 で直した。これは残った別種の4か所。

用語集に2語を足して解決。長い語から先に当てる作りなので、足すだけで
正しい説明（ギターの調弦）が出るようになった。
Death Metal・Stoner Rock・Nu Metal を実際に開いて確認済み（○9/✗0）。
