## C. 決めごとが要る

### C-1. SEO（検索から来てもらう）── 待ちの段階

**2026-09-02 に仕込みは完了。あとは待つだけ。**

**方式**：ジャンルごとに別ページは作らない（1枚試作して却下）。
地図の住所そのもの（`genre_roots.html?genre=…`）を573本、検索に載せる。
検索から来た人は、いつもの地図がそのジャンルのパネルを開いた状態で始まる。
用語の吹き出しも代表曲の再生も全部動く。

**済んだこと**
- 住所ごとに題名・説明文・canonical・og を書き換える仕組み（地図 v27.58）
- 検索や共有から来たときは `?genre=` を消さずに残す（リンクを渡せる）
- `sitemap.xml`（577本）と `robots.txt`
- Google Search Console に登録（HTMLファイルで所有者確認）
- sitemap を送信（受理済み）
- 3本だけ手作業で「見に来て」とお願い（krautrock / jazz / techno）

**チョロさんがやることは、もう無い。** 残り570本は sitemap 経由で
Google が自分のペースで見に来る。手作業では1日10件ほどの上限があるので
そもそもできないし、する必要もない。

### 2〜3日後に確かめること（クローディアから声をかける）

**いちばん大事な問い**：Google が JavaScript を動かして、
説明パネルの中身まで読んでくれるか。

 1. `site:genre-roots.com` で検索して、`?genre=krautrock` が出てくるか
 2. Search Console の「URL を検査」→「クロール済みページを表示」で、
    **パネルの中身（モトーリック等）が入っているか**

**読めていれば**この方式で決まり。残りは待つだけ。
**読めていなければ**案2へ切り替える。地図の2.28MBを
「見た目の指定」「データ」「動き」に分けて外に出し、ジャンルごとに
10KB程度の軽いページを作る（本物の地図が立ち上がる形は変えない）。
道具の下書きは `tools/genre_pages/build.py` にあるが、あれは
別ページ方式なので作り直しになる。半日仕事。

**時間の目安**
| 段階 | かかる時間 |

| 登録される（site: で出る） | 数時間〜数日 |
| 説明文の中の言葉で引っかかる | その数日後 |
| 「クラウトロック とは」で上位 | 数か月。Wikipedia が相手 |

### 記録が保管庫に届いているかの見かた（2026-09-02・解決済み）

**2026-09-02 19:58 に、記録が保管庫へ届くのを確認した。**

  https://github.com/chororinkob/genre-roots-logs

`access/2026-09-02.json` のような、日付の名前のファイルができていれば
記録が残っている。コミットは `genre-roots-server` の名前で入る。

サーバー側から見る場合（管理者のログインが要る）。

  https://genre-roots-server.onrender.com/admin/health

`log_repo` の中を見る。
 ・`last_push_ok` に時刻 … 保管庫へ届いた
 ・`last_push_error` に文字 … 届かなかった理由がそのまま出る
 ・`days_kept` … 保管庫に入っている日数
 ・`定期の係` … 背景で回る仕組みが生きているか

**【分かったこと】定期の係は本番で死んでいる（`定期の係: false`）。**
理由は突き止められていない。ただし Render の無料枠は誰も来ない時間が
続くとサーバーごと眠るので、そもそも定期の係はあてにできない。
記録が残るかどうかは「記録を受け取ったついでに書き出す」ほうが決めている。
書き出しの間隔は2分。眠って失われるのは、最大でも直近2分ぶん。

※ 鍵の期限は 2026-10-09。切れると記録もジャンル追加も止まる。
