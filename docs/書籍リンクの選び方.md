# 関連書籍（Amazonリンク）の選び方

各ジャンルの説明パネル、「成り立ち」の下に表示する書籍カルーセルの選定ルール。
ゆくゆく `genre_adder.py` の新規追加処理に組み込む前提の記録。

最終更新：2026-09-04

---

## 基本方針

**知名度で対象ジャンルを絞らない。** 有名なジャンルは検索すればどこでも情報が
出てくるが、マイナーなジャンルほど専門書の存在自体がネット上に埋もれていて、
紹介する価値が高い。知名度の高低に関係なく、全ジャンルを対象にする。

**手を抜いて「同じカテゴリーだから同じ3冊」で済ませない。** 大きなカテゴリー
（例：ヒップホップ系）の中でジャンルが細分化されている場合でも、必ず
ジャンルごとに個別のピンポイント検索を行う。カテゴリー共通の本を先に
決めて使い回す、という進め方はしない（結果的に同じ本になるのは構わないが、
探す手順自体は毎回ちゃんと行う）。

## 優先順位（1ジャンルにつき最大3冊）

1. **1冊目：そのジャンルをピンポイントで扱った本**を最優先で探す。
   見つかれば必ずこれを1冊目に置く。
2. **2〜3冊目：見つからなければ、そのジャンルが属する大カテゴリー全体を
   扱った本**でよい（例：ヒップホップ系全体の歴史書）。
   同じカテゴリー内の別ジャンルと本が重複してもかまわない。
3. 本が1冊も見つからないジャンルは、**0冊のままでよい**。無理に選ばない。
   枠自体を表示しない（`sp-books-wrap` が自動で隠れる）。

## ピンポイント本の探し方（手順）

1. **まず日本語・カタカナ名（別名/aliases）で検索する。** 英語名での検索は
   精度がかなり落ちる（実例：「Vaporwave 音楽」は本が0件でTシャツ等の
   雑貨しか出なかったが、「ヴェイパーウェイヴ 音楽」で検索すると、
   まさにこのジャンルの専門書が1位で出てきた）。
2. Amazon検索は `&i=stripbooks` を付けて本のカテゴリーに絞る。
   ただし本の該当が無いと、Amazon側が自動で全カテゴリーの検索結果
   （グッズ等）に切り替えてしまうことがあるので、結果が本当に本かどうか
   目視で確認する。
3. **1つの言い回しで「無い」と決めつけない。** 言い回しを変えて複数回
   試す（例：「オールドスクール ヒップホップ」だけでなく
   「ヒップホップ 起源 本」なども）。**ジャンル名そのものだけでなく、
   そのジャンルを象徴する人物名でも探す。** ジャンル名では見つからなくても、
   代表的なアーティスト・プロデューサーの伝記や作品解説本が実質的に
   ピンポイントの内容になっていることがある（実例：「Boom Bap」では
   見つからなかったが、「DJプレミア」（ブーンバップを象徴するプロデューサー）
   で検索したら専門書『DJプレミア完全版』が見つかった）。
4. タイトルが近そうでも、**実際に目次・章立てを検索して確認する**まで
   「ピンポイントで合っている」と判断しない。単に「ヒップホップ」という
   言葉が入っているだけの、時代もジャンルも扱いが広すぎる本は
   ピンポイント扱いにしない。
   - 良い実例：ゴールデンエイジ・ヒップホップに『ライムスター宇多丸の
     「ラップ史」入門』を採用した理由は、第3章のテーマが文字通り
     「ラップ黄金期の到来」だったから（目次を実際に調べて確認した）。
   - 悪い実例（やってしまった失敗）：最初、ヒップホップ全般の本6冊を
     ろくに確認せずGolden Age Hip Hopに並べてしまった。後で
     「Old School Hip Hopにも同じ本を使うのか」と聞かれて初めて、
     時代を区別せずに選んでいたことに気づいた。

## 実在確認（ハルシネーション対策）

- 本のタイトル・ASIN・表紙画像URLは、**必ず実際にAmazon商品ページに
  アクセスして確認したものだけ**を使う。AIが「それらしい本」を
  存在確認なしに答えることは絶対にしない（他の項目のファクトチェックと
  同じ理由）。
- 表紙画像はAmazon本体の商品画像URL（`m.media-amazon.com/images/I/...`）を
  そのまま使う。ホットリンクの制限が無いことは実測済み。
- Amazon Product Advertising API（自動で商品情報を取得する公式の仕組み）は
  **売上実績が無いと使えない**ため、今は使えない（新規アソシエイトは
  利用不可、と公式ヘルプに明記）。利用可能になっても、この文書の
  ピンポイント判定の基準は変わらない。

## データの持たせ方

```js
books:[
  {asin:"ASIN文字列", title:"書籍名", img:"表紙画像のURL"}
]
```

`books` フィールドが無い、または空配列のジャンルは、書籍カルーセルの枠
自体が表示されない（意図した仕様）。

## リンクの形式

```
https://www.amazon.co.jp/dp/{ASIN}?tag=genreroots-22
```

`genreroots-22` はチョロさんのAmazonアソシエイトID。

## 表示件数の上限

**最大3冊まで。** 理由：今の表紙画像のサイズだと、3冊ちょうどで
横スクロール無しに収まる（4冊目からはみ出す）。マウスでの横スクロールは
クリックしてのドラッグ操作が必要で、見てもらえない可能性が高いため、
スクロールに頼らない前提で3冊に絞っている。
